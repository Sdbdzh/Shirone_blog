> 一句话概括：校验码如果是「无密钥的确定性纯函数」，那么它就一定会在数据里留下恒等式——我们要做的不是猜算法，而是把所有可能的算法逐一试过去，看哪个对所有样本都成立。
>
> 本文所有卡号、余额、UID 均已匿名化或泛化；讨论对象是数据结构与数学方法本身。

## 一、问题设定

手里有一批 MIFARE Classic 1K 的 dump 文件（每张 1024 字节 = 64 块 × 16 字节）。其中只有 5 个块有非零内容，其余全是填充零。有效载荷集中在一个「余额块」上——两个互为备份的 16 字节块，格式未知，其中若干字节看起来像校验码。

目标：**在不参考任何既有文档的前提下，独立推导**

1. 这个块的完整字段布局；
2. 校验码位于哪几个字节、用什么算法算出；
3. 字段之间的代数关系。

素材：`10 张卡 × 2 个备份块 = 20 个样本`，每个样本 16 字节。

## 二、先看内存地图

第一步永远是把「哪些块有数据」数清楚。遍历 64 个块，统计非零出现次数：

```python
from collections import Counter

def blk(d, n):
    return d[n*16:(n+1)*16]

nz = Counter()
for data in dumps:                       # 10 张卡
    for n in range(64):
        if blk(data, n) != b"\x00" * 16:
            nz[n] += 1
```

结果非常干净：块 0（厂商块）、块 40/41/42/43 在 10/10 张卡上有数据；扇区 0–9、11–15 的**数据块全为零**，只有尾块（每扇区最后一块）存放了密钥。也就是说，这张卡的「业务数据」只占 4 个块，剩下都是 MIFARE 标准结构。

块 0 也顺手解析掉：

```
UID(4) | BCC(1) | SAK(1) | ATQA(2) | 厂商数据(8)
```

BCC = UID 四字节逐位异或，10/10 通过；SAK=0x08、ATQA=0x0400，标准的 Classic 1K、4 字节非随机 UID。

尾块是经典布局：

```
KeyA(6) | AccessBytes(3) | GPB(1) | KeyB(6)
```

10 张卡的 AccessBytes 全部是 `FF 07 80`，GPB 全部是 `0x69`，KeyA 与 KeyB 相同。控制台解码后，全卡所有扇区权限完全一致——没有分级、没有差异化区块。

> 插曲：块 41 的内容（10/10 张卡完全相同）字节排列恰好长得像一个尾块：`AA AA AA AA AA AA | AA 00 A0 | 01 | BB BB BB BB BB BB`。如果只扫一眼就下结论，很容易把它当成一个「特殊控制块」。但 MIFARE 的 Access Bits **只在真正的尾块生效**，块 41 是扇区 10 内的普通数据块。这个陷阱值得记一笔：格式相似不等于语义相同。

## 三、余额块的字节地图

把 20 个余额块排成表格，逐字节看分布。很快能发现几个「永远不变」和「跟着变」的位置：

| 偏移 | 观察到的行为 | 初步判断 |
|---|---|---|
| 0 | 随其他字节变化 | 校验码候选 |
| 1 | 随字节 2/3/4 变化 | 校验码候选 |
| 2–3 | 值域 0–65535，小端读出恰好等于卡面金额（分） | 余额主体 |
| 4 | 每卡固定小值 0x00–0x09 | 某种内部计数 |
| 5 | 恰好是字节 1 的按位取反 | 冗余副本 |
| 6–9, 12, 14 | 恒为 0x00 | 填充 |
| 10–11 | 单调递增的小整数 | 累计次数 |
| 13 | = (字节10 + 字节11) mod 256 | 字节和的校验 |
| 15 | 随交易变化，看起来不被前两个校验码覆盖 | 待定 |

到这一步，靠肉眼已经能猜出大半：`b0`/`b1` 是校验，`b2/b3` 是余额，`b10/b11` 是累计次数，`b13` 是累计次数的字节和，`b5` 是 `b1` 的取反副本。

但「猜」不是推导。真正的问题有两个：

- `b0` 到底覆盖了哪些字节？
- `b15` 是不是真的没有校验保护？

这两个问题用肉眼解决不了，需要数学方法。

## 四、线性结构探针：GF(2) 秩

先把每个块的 16 字节拼成一个 128 位大整数，排成 `20 × 128` 的 GF(2) 矩阵，求秩：

```python
def gf2_rank(rows, ncols):
    work = list(rows)
    r = 0
    for c in range(ncols):
        piv = next((i for i in range(r, len(work)) if (work[i] >> c) & 1), None)
        if piv is None:
            continue
        work[r], work[piv] = work[piv], work[r]
        for i in range(len(work)):
            if i != r and ((work[i] >> c) & 1):
                work[i] ^= work[r]
        r += 1
        if r == len(work):
            break
    return r

rank = gf2_rank([int.from_bytes(b, "little") for b in balance_blocks], 128)
# → 17
```

如果 16 字节彼此独立，20 个随机样本应该给出满秩 20。实测秩只有 **17**——说明存在 3 个线性维度被「吃掉」了，字节之间有确定的代数依赖。

这一步不告诉你公式是什么，但它给出了一个关键信号：**数据不是随机的，值得深挖**。而且零空间维数高达 111，意味着依赖关系不止一两条。

## 五、核心方法：仿射关系全空间穷举

现在进入正题。假设某个目标字节 `b_j` 满足一个「异或 + 常数」形式的仿射关系：

```
b_j = b_{i1} ⊕ b_{i2} ⊕ ... ⊕ b_{ik} ⊕ c
```

其中 `S = {i1, i2, ..., ik}` 是其他字节的某个子集，`c` 是常数。16 字节的所有子集只有 `2^16 = 65536` 个——完全可以穷举。

对每个子集 `S` 和每个目标字节 `j`（要求 `j ∉ S`，排除 `b_j = b_j` 这种废话），检查：

```python
d = (xor_of_bytes_in_S) ^ target_byte
若 d 在全部 20 个样本上恒定 → 找到一个关系式
```

同理，对「mod 256 加法」型关系：

```
b_j = (Σ_{i∈S} b_i − c) mod 256
```

也做一遍全空间穷举。

用 numpy 向量化，把 65536 个子集的异或和一次性算出（利用 `mask & (-mask)` 取最低位做 DP）：

```python
xor_tab = np.zeros((1 << 16, NS), dtype=np.uint8)
sum_tab = np.zeros((1 << 16, NS), dtype=np.uint8)
for mask in range(1, 1 << 16):
    low = mask & (-mask)
    bit = low.bit_length() - 1
    prev = mask ^ low
    xor_tab[mask] = xor_tab[prev] ^ arr[:, bit]
    sum_tab[mask] = (sum_tab[prev] + arr[:, bit]).astype(np.uint8)
```

然后对 16 个目标字节逐一筛选「差值恒定」的子集。几秒钟跑完。

### 为什么不会被假关系骗到

这是整个方法最漂亮的地方。一个**错误**的候选公式，在单个样本上碰巧成立的概率是 `1/256`；要在 20 个样本上全部成立，概率是

```
(1/256)^19 ≈ 10^-46
```

比连续中十次彩票头奖还低得多。所以凡是幸存下来的关系，几乎必然是固件真正使用的公式。

换句话说：**这里的「穷举」不是暴力破解，而是统计学判决**。20 个样本提供的约束，足以把 65536 个候选里的噪声全部滤掉。

### 极小解筛选

穷举会返回大量冗余解。比如因为 `b6~b9` 恒为零，会出现「b6 = b7」「b6 = b8」这类平凡关系；还有已找到关系的各种线性组合。

筛法很简单：把每个解表示成集合，只保留**按集合包含关系极小**的那些——即不能再删掉任何一个字节而仍然成立：

```python
def minimal_sets(sets):
    S = {frozenset(s) for s in sets}
    return [sorted(s) for s in S
            if not any(t < s for t in S)]
```

## 六、结果：完整的代数结构

穷举幸存下来的极小关系中，核心的几条是：

```
XOR 型:
  b0 = b1 ⊕ b2 ⊕ b3 ⊕ b4 ⊕ b5 ⊕ b10 ⊕ b11 ⊕ b13
  b5 = b1 ⊕ 0xFF                       (即 b5 = ~b1)

SUM 型 (mod 256):
  b1  = b2 + b3 + b4
  b13 = b10 + b11
  b5  = b10 + b11 + b13 + b15 − 1      ← 藏在最后一条
```

最后一条是意外收获。把 `b13 = b10 + b11` 代入，得到：

```
b15 = b5 − 2×b13 + 1  (mod 256)
    = 256 − b1 − 2×b13
```

20/20 样本全部满足。也就是说，**看起来最自由的字节 `b15`，其实被一个独立的镜像校验锁住了**。如果只检查前两个校验码就断言「b15 可以随便改」，就错了。

把 `b5 = ~b1` 代入 `b0` 的表达式，还能进一步化简：

```
b0 = 0xFF ⊕ b2 ⊕ b3 ⊕ b4 ⊕ b10 ⊕ b11 ⊕ b13
```

最终整块的依赖关系收敛为：

```
自由量: b2, b3 (余额)   b10, b11 (累计次数)   b4 (内部计数)
派生量: b1, b5, b13, b15, b0
填充量: b6–b9, b12, b14 恒为 0
```

**16 字节里只有 3 个自由量，其余 13 字节全部被代数关系确定。**

## 七、圆环重构：终极验证

公式解释数据不算本事，**能造出真块**才算。写一个构造函数，只喂三个自由量：

```python
def build_block(balance, counter, b4):
    b2, b3 = balance & 0xFF, (balance >> 8) & 0xFF
    b10, b11 = counter & 0xFF, (counter >> 8) & 0xFF
    b1 = (b2 + b3 + b4) & 0xFF
    b5 = 255 - b1
    b13 = (b10 + b11) & 0xFF
    b15 = (b5 - 2 * b13 + 1) & 0xFF
    b0 = b1 ^ b2 ^ b3 ^ b4 ^ b5 ^ b10 ^ b11 ^ b13
    return bytes([b0, b1, b2, b3, b4, b5,
                  0, 0, 0, 0, b10, b11, 0, b13, 0, b15])
```

从每个真实块里读出 `(余额, 累计次数, b4)`，重新构造，与原始块逐字节比较：

```
20/20 完全一致
```

这一步排除了所有「碰巧成立的伪公式」——如果任何一条关系搞错了，重构出来的块必然对不上。到这里，整个 16 字节块的代数结构算是彻底拿下了。

## 八、字段语义的真实实验

公式推出来了，但 `b4` 是什么仍不清楚。它在同一张卡上跨时点会变化，取值 0x00–0x09，与余额和使用次数都没有线性关系（mod 256 / mod 16 全系数扫描落空）。

后来拿到一组真实使用前后的样本（同一张卡，间隔一周，期间多次随机使用）：

| 样本 | 余额(分) | 累计次数 | b4 |
|---|---:|---:|---:|
| 使用前 | 1497 | 12 | 08 |
| 一周后 #1 | 435 | 23 | 09 |
| 一周后 #2 | 180 | 47 | 06 |
| 一周后 #3 | 406 | 42 | 03 |
| 一周后 #4 | 3 | 33 | 00 |

`b4` 有升有降，说明它不是单调计数器；另一张卡 24 次使用后保持不变，说明也不是每次交易都更新。至少能确定：它是机器自由写入的内部状态，且**所有样本都满足我们推导的校验关系**——机器自己写出的块和手工构造的块在数学上无法区分。

顺带确认了双备份的行为：充值时只更新其中一个块（两个块相差恰好 1000 分，累计次数相同），用水时两个块同时被写成相同值。

## 九、方法论小结

回顾整个过程，真正可复用的不是那些公式，而是这套**从样本反推确定性算法**的流程：

1. **清点样本**：确认数据粒度（多少样本、每个样本多少字节），判断约束是否充足——这里 20 个样本 / 16 字节的比例刚好够用；
2. **秩探针**：先算 GF(2) 秩，用「秩 < 样本数」确认存在线性依赖，避免在随机数据上白费功夫；
3. **全空间穷举**：把候选公式空间限制在 `2^16` 个子集内，用 DP + numpy 向量化一次算完；
4. **统计学判决**：用「对 N 个样本恒成立」作为筛子，错误公式的存活概率指数级小，无需人工辨别真假；
5. **极小解筛选**：用集合包含关系剔除冗余，只留真正独立的依赖；
6. **圆环验证**：用自由量重构完整样本，逐字节比对——这是唯一能一锤定音的步骤。

这套方法对任何**无密钥、确定性、字节级**的校验算法都适用：CRC、异或校验、加法校验、简单哈希的截断输出，都可以用同样的方式逆出来。它不适用的场景也很明确——如果校验里掺了密钥或随机数，任何跨样本恒等式都不存在，穷举会一无所获。反过来说，**穷举能成功本身，就证明了这套校验没有密钥参与**。
